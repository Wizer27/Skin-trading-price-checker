# skinwatch

Утилита для Steam Community Market: собирает цены на скины и показывает **10 позиций,
которые резко просели и которые выгодно покупать** — с учётом комиссии площадки.

* без зависимостей — только стандартная библиотека Python 3.8+;
* ведёт собственный журнал цен в SQLite, поэтому с каждым запуском видит падения точнее;
* консольная таблица или JSON для скриптов.

```
$ python3 -m skinwatch scan

Top 10 skins that dropped and look worth buying
fee 15% · reference = lowest of 24h median and your own history

 #  Skin                                   Now, USD  Usual, USD   Drop  Profit  Margin  Vol/24h  Lots
 ────────────────────────────────────────  ────────  ──────────  ─────  ──────  ──────  ───────  ────
 1  AK-47 | Redline (Field-Tested)             6.00        9.50  -36.8%  +2.07  +34.6%      900   400
 2  ...
```

## Как это работает

1. **Сбор.** `/market/search/render` отдаёт имя, самый дешёвый лот и количество лотов;
   Steam сейчас режет страницу до 10 позиций, поэтому `--pages 20` — это 200 позиций и
   20 запросов. Сортировка по ликвидности: там, где падение цены реально можно отыграть.
2. **Журнал.** Каждый скан пишется в SQLite (`~/.skinwatch/prices.db`). База и есть
   история цен: baseline = медиана прошлых снимков за `--window` дней.
3. **Проверка.** Для короткого списка кандидатов дёргается `/market/priceoverview` —
   медиана реальных продаж за 24 часа и объём продаж.
4. **Оценка.** Опорная цена = **минимум** из медианы за 24 ч и своей истории (чтобы не
   завышать прибыль). Дальше:

   ```
   drop   = (опорная − текущая) / опорная × 100
   net    = опорная × (1 − комиссия 15%)      # сколько реально придёт на кошелёк
   profit = net − текущая
   score  = margin% × confidence              # confidence растёт от объёма продаж и длины истории
   ```
5. **Фильтры.** Отсекаются неликвид, копейки, слишком дорогие лоты и падения, которые
   съедает комиссия.

Первый запуск работает только по медиане за 24 часа (истории ещё нет) — это нормально.
Начиная со второго запуска включается второй, независимый сигнал: своя история цен.

## Запуск

```bash
python3 -m skinwatch scan                    # CS2, USD, топ-10
python3 -m skinwatch scan --currency 5       # цены в рублях
python3 -m skinwatch scan --app 730,570      # CS2 + Dota 2
python3 -m skinwatch scan --pages 40 --enrich 60 --min-drop 12
python3 -m skinwatch scan --query "AK-47" --min-price 5   # только нужная линейка
python3 -m skinwatch scan --json > drops.json
python3 -m skinwatch history "AK-47 | Redline (Field-Tested)"
python3 -m skinwatch stats
python3 -m skinwatch apps                    # id игр и валют
```

`scan` — команда по умолчанию, `python3 -m skinwatch --top 5` тоже работает.

### Основные флаги

| Флаг | Что делает | По умолчанию |
|---|---|---|
| `--app` | id игры или список через запятую | `730` (CS2) |
| `--currency` | валюта Steam: 1=USD, 3=EUR, 5=RUB, 18=UAH, 37=KZT | `1` |
| `--pages` | страниц поиска, по 10 позиций каждая | `20` |
| `--sort` | порядок обхода маркета: `quantity` (ликвидные), `price`, `default`, `name` | `quantity` |
| `--query` | искать только по имени, например `"AK-47"` | — |
| `--top` | сколько скинов вывести | `10` |
| `--enrich` | сколько кандидатов проверить через priceoverview (0 — не проверять) | `40` |
| `--window` | сколько дней своей истории брать за baseline | `7` |
| `--min-drop` | минимальное падение, % | `8` |
| `--min-margin` | минимальная чистая прибыль после комиссии, % | `3` |
| `--min-volume` | минимум продаж за сутки | `5` |
| `--min-listings` | минимум лотов в продаже | `10` |
| `--min-price` / `--max-price` | коридор цен | `0.5` / `500` |
| `--fee` | комиссия долей (0.15 = 15 %) | по игре |
| `--delay` | пауза между запросами, с | `4` |
| `--db` | путь к журналу цен | `~/.skinwatch/prices.db` |
| `--transport` | `auto`/`curl`/`urllib` | `auto` |
| `--links` | печатать ссылки на маркет | — |
| `--json` | машинный вывод | — |

### Лимиты Steam

Steam пропускает примерно 20 запросов в минуту на все market-эндпоинты вместе, поэтому по
умолчанию между запросами 4 секунды и через `priceoverview` проверяется только короткий список. При 429 клиент сам ждёт
с экспоненциальной паузой. Скан по умолчанию — это ~30 запросов, то есть около полутора
минут; если ловите 429 пачками, поднимите `--delay`.

Steam режет часть TLS-отпечатков Python и отвечает 429 даже на первый запрос — поэтому
запросы по умолчанию идут через `curl` (есть в macOS и почти любом Linux). Явно выбрать
бэкенд: `--transport urllib` или `--transport curl`.

### Регулярный сбор

Чем чаще идут сканы, тем лучше baseline. Например, раз в 3 часа через cron:

```
0 */3 * * * /usr/bin/python3 -m skinwatch scan --quiet --json >> ~/skinwatch.log 2>&1
```

## Дисклеймер

Инструмент показывает статистику публичного маркета, а не инвестиционный совет.
Низкая цена бывает и по делу: скин может падать дальше, у предмета могут быть
торговые ограничения, а цена продажи — не гарантия того, что его купят.
